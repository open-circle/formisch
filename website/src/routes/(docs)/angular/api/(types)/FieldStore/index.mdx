# FieldStore

Field store interface that provides reactive access to the state of a field created with <Link href="../injectField/">`injectField`</Link> or the <Link href="../formischField/">`*formischField`</Link> directive.

## Generics

- `TSchema` <Property {...properties.TSchema} />
- `TFieldPath` <Property {...properties.TFieldPath} />

## Definition

- `FieldStore`
  - `path` <Property {...properties.path} />
  - `name` <Property {...properties.name} />
  - `input` <Property {...properties.input} />
  - `errors` <Property {...properties.errors} />
  - `isTouched` <Property {...properties.isTouched} />
  - `isEdited` <Property {...properties.isEdited} />
  - `isDirty` <Property {...properties.isDirty} />
  - `isValid` <Property {...properties.isValid} />
  - `setInput` <Property {...properties.setInput} />

### Explanation

Every reactive property of the field store is an Angular signal, so you call it as a function. The only exception is `path`, which is a plain value.

The `name` signal contains the JSON-stringified path of the field, which the <Link href="../formischControl/">`[formischControl]`</Link> directive writes to the `name` attribute of the element. It is also useful as the `id` of an input so that a label and an error message can reference it.

Use `setInput` to change the value of the field programmatically. It updates the input and triggers validation according to the `revalidate` config of your form.

The field store additionally carries an internal element-binding contract that the <Link href="../formischControl/">`[formischControl]`</Link> directive consumes. It is not part of the public API.
